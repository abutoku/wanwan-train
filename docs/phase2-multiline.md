# 第2フェーズ実装ドキュメント — 複数路線対応と乗り換え

作成日: 2026-07-04
ステータス: 実装完了

## 目的・スコープ

第2フェーズでは「他路線の追加」と「各駅で乗り換え路線を選択して乗換できる」機能を実装する。

乗車可能路線（今フェーズで追加する4路線 + 既存の山手線）:

| 路線 | 記号 | 区間 | 駅数 | 形状 |
|---|---|---|---|---|
| JR山手線 | JY | 環状（東京起点） | 30 | 環状 |
| 東京メトロ銀座線 | G | 渋谷 G01 〜 浅草 G19 | 19 | 直線 |
| 東京メトロ丸ノ内線 | M | 荻窪 M01 〜 池袋 M25 | 25 | 直線 |
| 東京メトロ日比谷線 | H | 中目黒 H01 〜 北千住 H22 | 22 | 直線 |
| 東急東横線 | TY | 渋谷 TY01 〜 横浜 TY21 | 21 | 直線 |

- 丸ノ内線の方南町支線（中野坂上〜方南町）は未収録（本線のみ）
- 上記以外の路線（JR他線・都営・他私鉄など）は引き続き**乗り換え案内としてのみ表示**
  （タップ不可の案内チップ）。次フェーズ以降で順次乗車可能にする
- スコープはユーザー確認済み（「主要路線のみ」を選択。メトロ全線・都営・東急全線はスコープ外）

## 主要な設計判断

### 1. データモデルの汎用化

`src/data/types.ts` に共通型を定義し、路線ごとにデータファイルを分割する。

```ts
interface Transfer { line: LineId; at?: string }   // at = 別名駅乗換（例: 日比谷駅）
interface Station { id; name; kana; en; number; transfers: Transfer[] }

interface RideableLine {
  name: string        // 例: 銀座線
  symbol: string      // 例: G（駅ナンバリング記号）
  color: string       // ラインカラー
  textColor: string   // バッジ上の文字色（ラインカラーとのコントラスト確保）
  loop: boolean       // 環状か直線か
  stations: Station[] // loop: 外回り順 / linear: 駅番号昇順
  directions?: { fwd: DirLabel; rev: DirLabel } // 環状線用の方向ラベル（外回り/内回り）
}
```

- `src/data/rideable.ts` が乗車可能路線のレジストリ（`RIDEABLE: Record<RideableLineId, RideableLine>`）
- `lines.ts`（乗換路線マスタ）に `yamanote` と新規路線（東武スカイツリーライン、
  みなとみらい線、東急大井町線ほか）を追加。乗車可能路線の LineId は lines.ts と共通

### 2. 方向の抽象化: fwd / rev

第1フェーズの `outer / inner` を汎用の `fwd / rev` に置き換える。

- `fwd` = 配列インデックス +1 方向（山手線: 外回り＝時計回り / 直線路線: 駅番号が増える方向）
- 方向ラベルは環状線は路線データに保持（外回り ⟳ / 内回り ⟲）、
  直線路線は終点駅名から自動生成（例:「浅草方面」「渋谷方面」）

### 3. 乗り換えの解決: 駅名マッチング

乗換先の駅を明示的なIDリンクではなく**駅名マッチング**で解決する
（`resolveTransfer(transfer, fromStation)`）。

- `transfer.at` があれば「駅」サフィックスを除いた名前、なければ現在駅名で
  乗換先路線の駅を検索（例: 山手線 御徒町 → 日比谷線は `at: '仲御徒町駅'` → 仲御徒町 H17）
- 見つかれば乗車可能 → InfoPanel のチップがタップ可能になる
- 見つからない（＝乗車可能路線でない）場合は案内のみのチップ
- 利点: 双方向の乗換リンクを二重管理しなくてよい。駅名の表記ゆれが唯一のリスクなので
  路線追加時は双方向で乗り換え可能なことを確認する

### 4. 地図描画: 環状 / 直線の2レイアウト

- **環状（LoopMap）**: 第1フェーズの円形描画をそのまま使用（複線・流れる破線・扇形タップ判定）
- **直線（LinearMap・新規）**: 1000×1000 viewBox 内に**つづら折り（サーペンタイン）**で配置
  - 1行あたり最大7駅で行数を決め、行ごとに左→右 / 右→左を交互に折り返す
  - 線路は1本描画（複線表現は環状のみ）。進行方向は流れる破線で表現
  - 駅ラベルは駅の下に40°回転で配置
  - タップ判定は駅ごとの矩形（スマホ対応）
- 電車（Train）は汎用化: `along(pos, dir) => {x, y, angle}` を地図側から受け取り、
  実数駅インデックス `pos` を Framer Motion でトゥイーンして線路上を走る
  - 環状: pos→角度・方向でトラック（外側/内側）を選択
  - 直線: pos→折れ線上の線形補間。方向転換時は向き（angle）が反転
  - 路線切替時は `key={lineId}` で再マウントして位置をリセット

### 5. ストア拡張（store.ts）

```
lineId: RideableLineId        // 現在乗車中の路線
direction: 'fwd' | 'rev'
transferFlash: boolean        // 乗り換え直後の演出用（2秒で消える）
```

- `transferTo(lineId, index)`: 停車中のみ受付。路線・現在駅を切り替え、
  目的地・再生状態をリセットし「のりかえ演出」を表示
- 直線路線の終端処理: 終点でそれ以上進めない場合 `stepForward` は無効、
  自動運転（再生）は終点到着で自動停止
- 直線路線の駅タップ: 目的地への方向が一意に決まるため**方向を自動で切り替えて**移動する
  （環状線は第1フェーズどおり選択中の方向を維持）
- `stopsBetween` は環状/直線で計算を分岐

### 6. UI変更

- ヘッダーの路線バッジ: 現在の路線名をラインカラーで表示（例: 「G 銀座線」）
- InfoPanel の乗り換えチップ:
  - 乗車可能路線 → タップで乗り換え（「のりかえ →」表示、停車中のみ有効）
  - 案内のみの路線 → 非インタラクティブなチップ
  - 直線路線の終点では「次の駅」欄に「終点」と表示
- Controls の方向ボタン: 路線に応じたラベル（外回り/内回り or 〜方面）
- CenterInfo: 駅ナンバリングバッジを路線カラーで表示、乗り換え直後は「のりかえたよ！🐾」

## 仕様解釈・判断メモ

- 「各駅で乗り換え路線を選択し乗換できるように」→ 停車中に InfoPanel の乗換チップを
  タップすると、その路線の対応する駅に乗り換える（移動中は不可）
- 乗り換え後は方向 `fwd`・停止状態にリセット（どちら方面に乗るかをユーザーが選び直す。
  本アプリの「向きを学ぶ」目的に合致）
- 直線路線の駅タップで方向を自動切替するのは、環状線と違い方向が一意で
  「逆向きに乗って終点で詰む」体験に学習価値がないため
- 直線路線の地図はつづら折り配置（実地理ではなくゲーム的な見やすさを優先。第1フェーズの
  山手線が等間隔配置なのと同じ判断）

ブラウザ（デスクトップ / モバイル390px幅）で以下を確認:

- 山手線 東京駅 → 丸ノ内線に乗り換え（M17 東京）、つづら折りマップ表示
- 直線路線の駅タップで方向が自動で切り替わり移動（東京 → 銀座 = 荻窪方面）
- 丸ノ内線 銀座 → 銀座線に乗り換え（G09）、浅草タップで終点まで移動

- 別名駅乗換: 銀座線 上野広小路 → JR山手線（御徒町駅）で山手線 JY04 に復帰
- 乗車不可路線（JR他線・都営など）は「案内のみ」チップでタップ不可
- モバイルレイアウト（地図上・パネル下）、直線マップの上部オーバーレイ表示
